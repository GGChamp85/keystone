# Support

## Getting help

- **Documentation**: start at [`docs/index.md`](docs/index.md) — the quickstart, guides, deployment runbooks and the configuration reference.
- **Bugs**: open an issue using the [bug report template](.github/ISSUE_TEMPLATE/bug_report.yml).
- **Feature requests**: open an issue using the [feature request template](.github/ISSUE_TEMPLATE/feature_request.yml).
- **Questions / usage help**: use [GitHub Discussions](../../discussions) if enabled, or the [question template](.github/ISSUE_TEMPLATE/question.yml).
- **Security vulnerabilities**: see [`SECURITY.md`](SECURITY.md) — do not use a public issue.

## Before asking

Run `keystone doctor` and include its output — most deployment questions turn out to be a missing env var, an unreachable service, or an air-gap egress rule, and `doctor`/the relevant runbook usually names the exact problem.

## Commercial support

The software is open source and maintained on a best-effort basis; no support agreement comes with it. Organisations that need one, or hands-on deployment help, should open a GitHub Discussion or contact the maintainers through the repository. `docs/enterprise/open-weights-risk-and-support.md` sets out who is responsible for what.
