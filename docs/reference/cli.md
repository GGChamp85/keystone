# CLI reference

Every `keystone` command, from the CLI's own `--help` (generated by `scripts/gen_cli_reference.py`; CI fails when this page is stale). The CLI is a real HTTP client against a running deployment (`KEYSTONE_INFERENCE_URL`, `KEYSTONE_API_KEY`; admin commands need `KEYSTONE_ROOT_ADMIN_TOKEN`), except `init`, `doctor`, `up`/`down`, `bundle` and `deploy`, which work on the machine they run on.

## keystone keys-rotate

```text
Usage: keystone keys-rotate [OPTIONS] {tenant_id} {key_prefix}

  Replace an API key without an outage: mints a new key with the same scopes and limits and expires
  the old one after --grace-hours (ADR 0004). Prints the new key exactly once.

Arguments:
  tenant_id   [required]
  key_prefix  The ks-xxxxxxxx prefix of the key to replace  [required]

Options:
  --grace-hours <int>  How long the old key keeps working; 0 = revoke now  [default: 24]
  --help               Show this message and exit.
```

## keystone up

```text
Usage: keystone up [OPTIONS]

  Bring up the Keystone stack — a real wrapper around `docker compose up -d` (+ optionally the
  sandbox image build and migrations), matching what the README's manual `make certs && make build
  && make up && make db-migrate` steps do in one command.

Options:
  --dev / --no-dev                Only infra (postgres/redis/qdrant) — no app/worker/sandbox-daemon
                                  [default: no-dev]
  --migrate / --no-migrate        Run alembic migrations once the stack is up  [default: migrate]
  --sandbox-images / --no-sandbox-images
                                  Build the sandbox runtime image too  [default: sandbox-images]
  --with-demo-model               Also start the no-GPU demo model (llama.cpp, Qwen2.5-Coder-0.5B) —
                                  pair with `keystone init --backend demo-cpu`
  --help                          Show this message and exit.
```

## keystone ingest

```text
Usage: keystone ingest [OPTIONS] {repository_url}

  Ingest a repository into the memory system's RAG index — a real wrapper around the existing POST
  /v1/keystone/ingest route (src/memory/ingestion.py's CodeIngestionPipeline). Incremental: a second
  run only re-embeds files that actually changed.

Arguments:
  repository_url  Git clone URL — must be on GIT_ALLOWED_HOSTS  [required]

Options:
  --branch <str>            [default: main]
  --max-file-size-kb <int>  Skip files larger than this  [default: 500]
  --help                    Show this message and exit.
```

## keystone init

```text
Usage: keystone init [OPTIONS]

  Guided setup — writes a real .env file (from .env.example) for `make up` to use. Run `keystone
  doctor` afterward to verify what's actually reachable.

Options:
  --output <str>   Where to write the .env file  [default: .env]
  --yes            Non-interactive: auto-generate all secrets, skip every other prompt
  --backend <str>  Coding model backend: demo-cpu (llama.cpp 0.5B, no GPU), single-gpu (vLLM serving
                   Qwen2.5-Coder-7B on one 24 GB GPU), frontier-proxy
                   (benchmarks/frontier_proxy.py), or self-hosted-gpu (the compose/Helm defaults).
                   Asked interactively when omitted.
  --help           Show this message and exit.
```

## keystone doctor

```text
Usage: keystone doctor [OPTIONS]

  Diagnose your Keystone deployment — real checks against Postgres (and its migration revision),
  Redis, Qdrant, the sandbox daemon, model endpoints, the git host, package mirrors, secret
  strength, TLS certificate validity, free disk, and the running app's own readiness when
  KEYSTONE_INFERENCE_URL is set — each reporting exactly what's wrong (and often how to fix it), not
  just pass/fail.

Options:
  --help  Show this message and exit.
```

## keystone finetune guided

```text
Usage: keystone finetune guided [OPTIONS]

  Describe → plan & cost → approve → train. Builds a dataset from the repositories' real history and
  this tenant's accepted agent tasks, shows the plan, and starts the job once you approve it.

Options:
  --repo <str>                   Allow-listed git URL to learn from (repeatable)  [required]
  --goal <str>                   What the adapter should get better at, in plain words  [required]
  --base-model <str>             Catalog model id, or 'auto' for the default SLM  [default: auto]
  --epochs <int range>           [default: 1; x>=1]
  --holdout-ratio <float range>  [default: 0.2; 0.05<=x<=0.5]
  --gpu <str>                    Target GPU as NAME:VRAM_GB (repeatable); omitted = detect on the
                                 server
  --gpu-hourly-cost <float>      Your GPU price in USD/hour, for the cost line
  -y, --yes                      Approve the plan without asking
  --force / --no-force           Approve even if the planner says it does not fit  [default: no-
                                 force]
  --help                         Show this message and exit.
```

## keystone finetune export

```text
Usage: keystone finetune export [OPTIONS] {job_id}

  Export a completed job's adapter: merged Hugging Face checkpoint, GGUF (llama.cpp), or AWQ 4-bit.

  Runs on the server in the background; the artifact's path and size land under the job's
  metrics.exports.<format>. --wait polls until then.

Arguments:
  job_id  [required]

Options:
  --format <str>          merged | gguf | awq  [default: gguf]
  --quant <str>           GGUF only: f32 | f16 | bf16 | q8_0 (default q8_0)
  --wait                  Poll until the export finishes and print the artifact
  --poll-seconds <float>  Polling interval with --wait  [default: 5.0]
  --help                  Show this message and exit.
```

## keystone deploy runpod-serverless

```text
Usage: keystone deploy runpod-serverless [OPTIONS]

  Create (or reuse) a RunPod Serverless vLLM endpoint serving an open-weight model, scaled to zero
  when idle — a real GPU backend with no hardware to buy. Needs RUNPOD_API_KEY in .env. Prints the
  exact .env lines that point a role at it.

Options:
  --name <str>              Endpoint/template name — re-running with the same name reuses them
                            [default: keystone-coder]
  --model <str>             Hugging Face model id to serve  [default:
                            Qwen/Qwen2.5-Coder-7B-Instruct]
  --served-name <str>       The `model` name clients send  [default: keystone-coder]
  --gpu-tier <str>          24gb | 80gb — which serverless GPU pool to schedule on  [default: 24gb]
  --max-model-len <int>     [default: 16384]
  --workers-max <int>       Upper bound on concurrent GPU workers (cost ceiling)  [default: 2]
  --idle-timeout <int>      Seconds idle before a worker scales to zero  [default: 60]
  --destroy / --no-destroy  Delete the endpoint and template of this name instead  [default: no-
                            destroy]
  --help                    Show this message and exit.
```

## keystone deploy cloud

```text
Usage: keystone deploy cloud [OPTIONS]

  Stand up (or tear down) a GPU Kubernetes pilot on AWS, Azure or GCP — a thin wrapper around `tofu
  -chdir=infra/opentofu/environments/<cloud>-<env> init|plan|apply|destroy` (Terraform is used when
  OpenTofu is not installed) and, with --helm-install, the matching Helm install. Every command is
  printed before it runs. See docs/guides/deploy-<cloud>.md for what you get, what it costs, and
  what has and has not been verified.

Options:
  --cloud <str>      aws | azure | gcp  [required]
  --env <str>        Environment name — runs in infra/opentofu/environments/<cloud>-<env>  [default:
                     pilot]
  --plan             init + plan, change nothing (the default)
  --apply            init + apply — asks for the usual yes/no first
  --destroy          init + destroy the whole environment — asks for yes/no first
  --var-file <path>  Extra -var-file (terraform.tfvars in the environment directory is loaded
                     automatically)
  --helm-install     Run `helm upgrade --install` with values-client-vpc.yaml + values-<cloud>.yaml
                     against the current kubeconfig context — after --apply, or on its own once the
                     cluster exists
  --help             Show this message and exit.
```
