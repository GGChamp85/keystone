# Roadmap

Public tracking of where Keystone is headed. Tracks the phased plan for bringing Keystone Agents to Codex/Cursor-class quality with company-specific fine-tuning that measurably beats plain RAG. Each phase ships behind config flags with its own tests; phases are independently shippable.

A checked box means the phase's real, testable scope is done and covered by real tests against real infrastructure (Postgres/Redis/Qdrant/sandbox/git host) — not that every GPU-dependent behavior has been observed on real hardware, since this project's own development environment has no GPU. Each phase's status line says exactly what that gap is where one exists; nothing here is checked on the strength of code that has never actually run.

- [x] **Phase 0 — GLM-5.3-Flash model support**: GLM-5.3-Flash (zai-org, MIT) is the default coding model, Qwen2.5-Coder-32B-Instruct the fallback; vLLM bumped for MoE + native tool-calling, tool-parser flags verified against vLLM's real parser registry. *Config/infra complete and unit-tested; the actual tool-call round-trip against a live GLM endpoint (`scripts/smoke_glm_toolcall.py`) needs real GPU hardware to verify.*
- [x] **Phase 1 — Real git workflow**: the background agent clones the real repo into its sandbox, runs the repo's real test suite, commits to a branch, and opens a pull request against a real Gitea instance — not a JSON blob of file contents. Verified by actually running `tests/test_git_workflow_integration.py` end to end against a live Gitea 1.22 container, a live sandbox daemon, and a live gVisor sandbox (this test has real infra requirements and, as far as this project's history shows, had never actually been executed before) — doing so surfaced and fixed two real bugs no mock would have caught: the sandbox's egress firewall never actually allowed a deployment's real configured `GIT_ALLOWED_HOSTS`, only the placeholder default hostname, silently breaking the README's "Connect your own git server" path for anyone who configured it; and `docker-compose.yml`'s sandbox network had no pinned name, so Compose's project-name prefixing made every network-enabled sandbox fail outright.
- [x] **Phase 2 — Agentic loop engineering**: tool use (read/grep/run/patch) inside the coding loop instead of single-shot full-file rewrites; a review gate that fails closed; re-planning after repeated failures; context budgeting for large diffs.
- [x] **Phase 3 — Quality gates + memory**: enforced lint/typecheck/security scanning before review; a per-repo and per-tenant memory system the agent learns from and a human can inspect, pin, and forget — exposed via `keystone memory ...`, the web UI's Memory panel, and an OpenCode plugin.
- [x] **Phase 4 — Multi-developer + large-repo scale**: user/role identity (`admin`/`lead`/`developer`) on every task and memory action, a Redis-backed per-tenant/per-user concurrency limiter, automatic PR-status polling into task feedback, and incremental AST-aware, per-tenant repo indexing for monorepos.
- [ ] **Phase 5 — Fine-tuning that beats RAG**: real, tested infrastructure end to end — three data sources (git history, accepted trajectories, repo pretraining text), a stratified train/holdout manifest, eval-aware trainers, an adapter registry with promote/rollback, LoRA-serving vLLM flags, adapter-aware routing through every real inference call site (including the OpenAI-compatible gateway), a Temporal-backed runner with an asyncio fallback, a full REST API, `keystone finetune ...` CLI commands, and a 3-step web wizard. *Still open: the automatic "only promote if it measurably beats base+RAG" verdict gate described in this phase isn't wired up yet (promotion is a manual human action today), and no adapter has been trained on a real GPU — only a CPU LoRA smoke path with a 0.5B model has been run in this dev environment.*
- [ ] **Phase 6 — Benchmarks + eval, including frontier models**: a small, fully real 3-task benchmark harness exists and has been run for real (`benchmarks/`) — real sandbox-executed pass/fail (no LLM-as-judge), a real token-cost comparison, and gated frontier clients that only activate with a real API key present. *Still open: the multi-file-repo, SWE-bench-lite-style suite this phase actually calls for (10–20 real repos with real failing tests, run through the full agent loop via `agent_runner.py`, not single-function completions) hasn't been built.*
- [ ] **Phase 7 — Enterprise ease of use**: a guided `keystone init`/`up`/`doctor` CLI and a single validated config file are not built yet — today's on-ramp is the manual `make` targets in [Run it locally](README.md#run-it-locally-in-10-minutes).
- [x] **Phase 8 — Public repository hygiene**: `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, issue/PR templates, CI (lint/type-check/tests/Helm lint+template/shellcheck/web build), CodeQL, and Dependabot are all real and green. *A published documentation site (MkDocs) isn't set up — docs currently live as markdown files under `docs/`.*
- [ ] **Phase 9 — Cost transparency + improvement suggestions**: not started — live per-task token/cost breakdown, pre-task cost estimates, hard budget enforcement, and an evidence-backed suggestions engine are still designed but unbuilt.

See `CHANGELOG.md` for what has already shipped. Contributions toward any unchecked item — or the noted gaps inside checked ones — are welcome; see `CONTRIBUTING.md`.
